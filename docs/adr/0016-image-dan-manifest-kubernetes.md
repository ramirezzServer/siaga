# 0016. Image layanan Go dan manifest Kubernetes pipa data

Tanggal: 2026-09-26 · Status: diterima

## Konteks

Sampai fase 1e-2a, ingest dan geo-processor hanya jalan lewat `make ingest` dan `make geo` di WSL. Dokumen arsitektur menetapkan produksi di k3s pada satu VM ARM Oracle Always Free (2 OCPU / 12 GB), image di GitHub Container Registry, image ditandatangani cosign dengan SBOM, container non-root dengan filesystem read-only, NetworkPolicy default deny, dan migrasi database sebagai Kubernetes Job sebelum deploy. Lingkungan lokal (k3d + Tilt) harus memakai manifest yang sama dengan produksi.

Fase 1e-2b dipecah tiga: **1e-2b-1** (ADR ini) image, job CI, dan manifest ingest + geo-processor; **1e-2b-2** OTel Collector, Garage di cluster, Secret SOPS; **1e-2b-3** retensi arsip dan backup ke Oracle Object Storage setelah data arsip seminggu terkumpul.

## Keputusan

1. **Satu Dockerfile untuk semua layanan Go** (`deploy/images/go/Dockerfile`). Layanan dipilih dengan build arg `SERVICE`, binary dengan `BINARIES`, dan ENTRYPOINT dengan `--target` (exec form tidak bisa memakai ARG). Image ingest berisi `ingest`, `archive`, dan `replay`; image geo-processor berisi `geo-processor`, `import-regions`, `goose`, dan folder `/migrations`. `river-snap` dan `calibrate-dedup` tetap alat laptop.
2. **Build per modul dengan `GOWORK=off`.** go.mod layanan sudah punya `replace` ke `libs/go`, dan `go tool goose` memang harus jalan tanpa workspace (ambiguous import genproto). Lapisan `go mod download` hanya bergantung pada go.mod/go.sum, dan cache modul serta build memakai cache mount BuildKit.
3. **Cross-compile, bukan emulasi.** Tahap build berjalan di `$BUILDPLATFORM` dan meng-compile ke `$TARGETARCH` (`CGO_ENABLED=0`), jadi image `linux/arm64` untuk VM Oracle dibangun di runner amd64 tanpa QEMU.
4. **Runtime `gcr.io/distroless/static-debian13:nonroot`.** Tanpa shell dan package manager; sertifikat CA dan tzdata sudah ada. User 65532. `-trimpath -ldflags "-s -w -X main.version=<commit>"`, jadi `service.version` di telemetri berisi commit image. goose diberi versinya sendiri lewat `-X main.version` (versi dari `go list -m`) dan dibangun tanpa driver selain PostgreSQL.
5. **Job CI `images`** (matrix per layanan): build amd64, uji asap (`scripts/image-smoke.sh`: tiap binary bisa jalan dengan `--read-only --network none`, user 65532, `/migrations` sama dengan repo), Trivy CRITICAL/HIGH yang sudah ada perbaikannya. Hanya di push ke `main`: build `linux/amd64,linux/arm64`, push ke `ghcr.io/ramirezzserver/siaga-<layanan>` dengan tag `sha-<commit>` dan `main`, SBOM dan provenance BuildKit, lalu tanda tangan cosign keyless (OIDC GitHub) pada digest. Pull request hanya build dan uji, tanpa push.
6. **Kustomize, bukan Helm chart per layanan.** Dokumen arsitektur menyebut Helm chart dengan `values-local.yaml`/`values-prod.yaml`. Repo sudah memakai Kustomize (`deploy/k8s/base`, `deploy/k8s/local`) dan Tilt memanggil `kustomize()`, Argo CD mendukung Kustomize langsung, dan perbedaan lokal–produksi di pipa data cukup berupa nama image dan beberapa variabel, jadi dipakai base per layanan (`deploy/k8s/apps/<layanan>`) dan overlay `local`/`prod`. Chart pihak ketiga (NATS, CloudNativePG) tetap lewat Helm. Konfigurasi non-rahasia di ConfigMap hasil generator (overlay menimpa dengan `behavior: merge`, hash di nama memicu rollout); rahasia hanya lewat Secret.
7. **Bentuk workload.** Satu replika dengan strategi `Recreate` untuk keduanya: dua ingest bersamaan menggandakan pemakaian kuota sumber karena anggaran request dihitung per proses, dan relay outbox serta putaran kedaluwarsa geo-processor belum dirancang untuk banyak instance. Probe `startup`/`liveness` ke `/healthz`, `readiness` ke `/readyz`. `runAsNonRoot`, `readOnlyRootFilesystem`, semua capability dibuang, seccomp `RuntimeDefault`, token service account tidak dipasang, `/tmp` berupa emptyDir. `GOMEMLIMIT` diisi dari batas memori container. Request 50m CPU / 64 Mi, batas memori 256 Mi per layanan (anggaran "5 layanan Go 0,3 GB" di dokumen arsitektur dihitung dari pemakaian, batas adalah plafon). Tanpa batas CPU supaya tidak kena throttling CFS pada VM 2 OCPU. `OTEL_RESOURCE_ATTRIBUTES` membawa nama namespace, pod, dan node.
8. **Koneksi database dari Secret CloudNativePG.** `DATABASE_URL` dirakit dengan ekspansi `$(VAR)` Kubernetes dari Secret basic-auth `siaga-db-geo` (password hex acak, aman tanpa URL-encode) dan host/port/nama/sslmode di ConfigMap (bawaan `siaga-db-rw`, `sslmode=require`; produksi bisa diarahkan ke Pooler).
9. **Migrasi sebagai Job `geo-processor-migrate`** dengan image geo-processor dan `goose up` (tabel `ref.goose_db_version`, sama dengan `make migrate`). Koneksi lewat `GOOSE_DRIVER`/`GOOSE_DBSTRING`, bukan argumen, supaya password tidak terlihat di daftar proses. Di Argo CD menjadi hook `PreSync` dengan `BeforeHookCreation`; di Tilt menjadi resource yang ditunggu geo-processor. Import wilayah tetap dari laptop lewat port-forward karena data batas wilayah diunduh di sana.
10. **NetworkPolicy per layanan.** ingest: masuk hanya ke port status dari namespace `siaga`; keluar ke DNS cluster, pod di namespace `siaga` (NATS, Garage, OTel Collector), dan internet port 80/443 selain alamat privat. geo-processor dan Job migrasinya: tanpa akses internet. Default deny untuk seluruh namespace menyusul setelah Garage, Collector, dan NATS punya policy sendiri (1e-2b-2).
11. **Job CI `manifests`**: render overlay `local` dan `prod` dengan kustomize, validasi `kubeconform -strict` untuk Kubernetes 1.33 (CRD CloudNativePG dilewati), dan Trivy misconfig CRITICAL/HIGH pada overlay prod. Overlay lokal tidak dipindai karena membawa Mailpit (alat dev, image pihak ketiga yang jalan sebagai root).
12. **Dashboard: keterlambatan sumber diukur saat metrik dikumpulkan.** Panel "Keterlambatan sumber" dan "Sumber tepat waktu" (ADR 0015) memakai `time() - last_success`, yang ikut menghitung jeda ekspor metrik (60 detik) dan pengiriman ke Grafana; `bmkg-autogempa` (interval 30 detik) tampil ±2,8× padahal sehat. Rumus baru `timestamp(x) - x + clamp_min(time() - timestamp(x) - $ekspor_metrik, 0)`: umur pada saat SDK mengumpulkan metrik (timestamp sampel OTLP adalah waktu kumpul), ditambah kelebihan bila metrik berhenti datang lebih lama dari jeda ekspor. `$ekspor_metrik` adalah variabel dashboard tersembunyi (60, sama dengan `OTEL_METRIC_EXPORT_INTERVAL`). Penyebut "Sumber tepat waktu" memakai `last_over_time(...[1h])`, jadi ingest yang mati terlihat 0% setelah seri metriknya hilang (±5 menit), bukan kosong.

## Konsekuensi

- Tilt (profil full) kini membangun kedua image dan menjalankan Job migrasi lalu geo-processor; ingest tidak otomatis jalan (`auto_init=False`) supaya tidak menggandakan kuota bila `make ingest` juga hidup. `scripts/dev-secrets.sh` membuat Secret `siaga-ingest` dari key OpenAQ/FIRMS di `.env` bila ada.
- Sampai 1e-2b-2, manifest mengosongkan `INGEST_ARCHIVE_URL` dan `OTEL_EXPORTER_OTLP_ENDPOINT` (Garage dan Collector belum ada di cluster): ingest di cluster tidak mengarsipkan payload dan tidak mengirim telemetri.
- Overlay prod baru berisi pipa data; platform (CloudNativePG, NATS, Garage, Collector) dan Secret SOPS menyusul, bootstrap cluster di fase 2. Tag `main` di overlay prod diganti pipeline CD dengan tag `sha-<commit>` saat Argo CD dipasang.
- Paket GHCR milik akun pribadi bisa dibuat privat pada push pertama; periksa visibilitasnya sekali di pengaturan paket dan jadikan publik supaya k3s bisa pull tanpa kredensial.
- Image dasar (`golang`, `distroless`) belum dipin ke digest; Renovate akan mengusulkan pin setelah GitHub App-nya dipasang.
- `make images`, `make images-smoke`, dan `make k8s-check` menjalankan hal yang sama dengan CI di laptop.
