# 0017. Garage, OTel Collector, secret SOPS, dan default deny di cluster

Tanggal: 2026-09-26 · Status: diterima

## Konteks

Setelah fase 1e-2b-1 (ADR 0016), ingest dan geo-processor punya image dan manifest, tetapi di cluster keduanya belum lengkap: `INGEST_ARCHIVE_URL` dan `OTEL_EXPORTER_OTLP_ENDPOINT` kosong karena Garage dan OTel Collector baru ada di Compose lite, key OpenAQ/FIRMS hanya bisa masuk lewat `scripts/dev-secrets.sh` di laptop, dan NetworkPolicy baru membatasi dua layanan itu. Dokumen arsitektur menetapkan: Garage di cluster, metrik/log/trace produksi ke Grafana Cloud free tier lewat OpenTelemetry, secret terenkripsi di repo dengan SOPS + age dan didekripsi hanya di cluster, dan NetworkPolicy default deny. Fase 1e-2b-2 (ADR ini) menutup bagian itu; retensi dan backup arsip menyusul di 1e-2b-3.

## Keputusan

1. **Garage satu node sebagai StatefulSet** (`deploy/k8s/platform/garage`), image dan mode sama dengan Compose (`dxflrs/garage:v2.3.0`, `server --single-node --default-bucket`, sudah teruji di fase 1e-1): layout, bucket `siaga-arsip`, dan access key dibuat saat start secara idempotent dari Secret `siaga-garage`, tanpa Job inisialisasi. Volume `meta` (1 Gi) dan `data` (10 Gi) dari volumeClaimTemplates; node ID tersimpan di `meta`, jadi pod bisa dijadwalkan ulang. Beda dari Compose: `compression_level = "none"` (payload arsip sudah gzip) dan `block_ram_buffer_max = "32MiB"` (buffer kirim ke node lain tidak berguna untuk satu node). Jalan sebagai UID 65532 dengan root filesystem read-only. Probe startup/readiness ke `/health` admin API (200 bila layout lengkap dan semua partisi punya quorum), liveness cukup port terbuka.
2. **ingest langsung mengarsipkan di cluster**: `INGEST_ARCHIVE_URL=s3://siaga-arsip/raw?endpoint=http://garage:3900` (awalan sama dengan Compose, jadi alat `archive`/`replay` berlaku tanpa perubahan), access key dibaca dari Secret `siaga-garage` (`GARAGE_DEFAULT_ACCESS_KEY`/`SECRET_KEY`) supaya Garage dan ingest tidak memegang salinan terpisah. Kegagalan membuka arsip tetap menggagalkan start (ADR 0014), jadi Tilt menunggu Garage dulu.
3. **OTel Collector distribusi `otelcol-k8s` 0.161.0** (`deploy/k8s/platform/otel-collector`), bukan `contrib` (lebih kecil, sudah berisi semua yang dipakai: receiver OTLP dan Prometheus, processor `memory_limiter`/`resource`/`batch`, exporter OTLP/HTTP, extension `health_check`). Manifest biasa, bukan operator atau chart: satu Deployment tanpa akses API Kubernetes (atribut pod sudah dikirim layanan lewat `OTEL_RESOURCE_ATTRIBUTES`). Layanan mengirim OTLP/HTTP ke `otel-collector:4318` tanpa token; **hanya Collector yang memegang kredensial Grafana Cloud** (Secret `siaga-otel-collector`: `OTLP_UPSTREAM_ENDPOINT`, `OTLP_UPSTREAM_AUTHORIZATION`). Satu exporter untuk ketiga sinyal, gzip, antrean 500 batch dan retry 10 menit untuk jaringan putus sesaat.
4. **Metrik platform di-scrape Collector tiap 60 detik** (sama dengan `OTEL_METRIC_EXPORT_INTERVAL`): sidecar `prometheus-nats-exporter` dari chart NATS (`promExporter.enabled`, target `nats-0.nats-headless:7777`), `/metrics` Garage (bearer `GARAGE_METRICS_TOKEN`), dan metrik internal Collector. Untuk menjaga seri aktif free tier, NATS dibatasi ke metrik tingkat server (isi stream dan antrean consumer sudah dikirim geo-processor lewat `natsx`) dan Collector ke `otelcol_*`; hasilnya ±55 seri. Processor `resource` mengisi `service.namespace=siaga` dan `deployment.environment.name` hanya bila belum ada, jadi label `job` hasil scrape seragam dengan layanan (`siaga/nats`, `siaga/garage`, `siaga/otel-collector`). Nama metrik di Grafana Cloud mengikuti terjemahan OTLP→Prometheus (counter Garage `api_s3_request_counter` menjadi `api_s3_request_counter_total`); diuji dengan Prometheus 3.15 sebagai penerima OTLP.
5. **Secret produksi: satu `SopsSecret` terenkripsi** (`deploy/k8s/prod/secrets.enc.yaml`) yang berisi semua Secret produksi (`siaga-db-*`, `siaga-garage`, `siaga-ingest`, `siaga-otel-collector`) dan didekripsi di cluster oleh **sops-secrets-operator** (isindir, multi-arch, SOPS 3.13). Alternatifnya KSOPS (plugin Kustomize di Argo CD): butuh kunci age saat `kustomize build`, sehingga job CI `manifests` tidak bisa merender overlay prod tanpa kunci. Dengan operator, render tetap murni (CR hanya YAML), CI memvalidasi tanpa kunci, dan Argo CD tidak butuh plugin. Operator mengabaikan MAC SOPS karena CR selalu diubah Kubernetes (namespace, label), tetapi isi terenkripsi tetap terlindungi AES-GCM per nilai.
6. **Aturan SOPS** (`.sops.yaml`): hanya `data`/`stringData` yang dienkripsi (`encrypted_regex`), jadi nama secret dan key tetap terbaca saat review; indentasi YAML 2 spasi supaya lolos Prettier. Recipient awal adalah kunci age pribadi pemilik repo (`~/.config/sops/age/keys.txt`, tidak pernah di-commit); kunci age cluster ditambahkan saat bootstrap produksi (fase 2) dengan `sops updatekeys`, bersamaan dengan pemasangan operator (Helm, `secretsAsFiles` + `SOPS_AGE_KEY_FILE`).
7. **`make secrets-prod`** (`scripts/prod-secrets.sh`) membuat kunci age bila belum ada, mengisi recipient di `.sops.yaml`, lalu membuat atau melengkapi file: nilai lama tidak pernah diubah, password dan token dibuat acak, key OpenAQ/FIRMS diambil dari `.env`, kredensial Grafana Cloud ditanyakan (token khusus produksi, bukan token laptop). Plaintext hanya lewat pipa ke `sops encrypt`, tidak pernah ditulis ke disk; file hanya diganti bila isinya berubah. `make secrets-grafana` merotasi token, `make secrets-edit` membuka file lewat `sops edit`.
8. **Penjaga plaintext**: `scripts/sops-check.sh` (dijalankan `make k8s-check` dan CI) memastikan setiap `*.enc.yaml` punya metadata SOPS dengan recipient age dan MAC, dan setiap nilai di bawah `data`/`stringData` berbentuk `ENC[AES256_GCM,…]`, tanpa butuh kunci. gitleaks tetap berjalan di pre-commit dan CI (teruji tidak menandai file terenkripsi).
9. **Lokal tetap memakai `scripts/dev-secrets.sh`**, bukan SOPS, dengan nama Secret dan key yang sama dengan produksi: password database acak, Garage dari nilai `.env` (satu set kredensial arsip di laptop), key sumber dari `.env`, dan tujuan OTLP dari `OTEL_EXPORTER_OTLP_*` di `.env` (endpoint `127.0.0.1` diganti `host.k3d.internal` untuk Grafana lokal; `OTLP_BIND=0.0.0.0` membuka port OTLP-nya ke jaringan Docker). Dokumen arsitektur menyebut SOPS dengan kunci lokal untuk lingkungan lokal; ini disederhanakan karena secret lokal hanya hidup di cluster laptop dan tidak pernah masuk repo, sedangkan jalur SOPS diuji penuh saat bootstrap produksi.
10. **NetworkPolicy default deny untuk seluruh namespace** (`deploy/k8s/platform/networkpolicy`): `default-deny` (semua pod, masuk dan keluar) dan `allow-dns` (semua pod ke CoreDNS), lalu izin eksplisit per komponen. ingest: keluar ke NATS 4222, Garage 3900, Collector 4318, dan internet 80/443 selain alamat privat. geo-processor dan Job migrasinya: keluar ke PostgreSQL 5432, NATS, Collector. NATS: masuk 4222 hanya dari ingest, geo-processor, dan nats-box; 7777 hanya dari Collector; tanpa egress. Garage: masuk 3900 dari ingest dan 3903 dari Collector; tanpa egress. Collector: masuk OTLP dari namespace; keluar ke NATS 7777, Garage 3903, dan internet 443 (overlay lokal menambah 4318 ke alamat privat untuk Grafana lokal). CloudNativePG (`cnpg.io/cluster=siaga-db`, termasuk Job initdb): masuk 5432 dari geo-processor, 5432/8000 dari operator (`cnpg-system`) dan sesama instance; keluar ke sesama instance dan API server Kubernetes (6443/443 ke alamat privat, karena kube-router k3s mengevaluasi policy setelah DNAT Service `kubernetes`). Valkey dan Mailpit belum punya klien, jadi tertutup penuh. Port-forward dari laptop (Tilt, kubectl) tidak terpengaruh.
11. **Dashboard** mendapat baris "Platform di cluster": status target scrape, pesan/koneksi/memori/penyimpanan NATS, request dan galat S3 Garage, ruang disk dan tulis blok, serta data yang dikirim, gagal dikirim, dan antrean Collector. Baris ini kosong di Compose lite (tanpa Collector).

## Konsekuensi

- Overlay prod kini berisi pipa data, Garage, Collector, NetworkPolicy, dan `SopsSecret`; yang tersisa untuk fase 2 adalah bootstrap cluster (CloudNativePG, NATS, sops-secrets-operator dengan kunci age cluster, Argo CD). `make k8s-check` gagal dengan pesan jelas bila `secrets.enc.yaml` belum dibuat.
- Kehilangan kunci age pribadi sebelum kunci cluster ditambahkan berarti semua secret produksi harus dibuat ulang (belum ada data produksi, jadi murah); simpan salinannya di password manager.
- Default deny bisa memutus komponen baru yang lupa diberi policy. Setiap layanan fase berikutnya (core-api, alert-engine, dan seterusnya) wajib membawa NetworkPolicy sendiri dan ditambahkan ke daftar klien NATS/PostgreSQL/Garage yang dipakainya.
- NetworkPolicy dan manifest platform belum pernah dijalankan di k3s (profil full belum dicoba); CloudNativePG di balik default deny adalah bagian yang paling mungkin perlu penyesuaian.
- Collector menambah ±100 Mi RAM (batas 256 Mi) dan Garage ±100 Mi (batas 384 Mi), masih di dalam anggaran "Argo CD, Traefik, OTel Collector, k3s" dan "NATS, Valkey, Garage, Martin" dokumen arsitektur.
- Chart NATS di Tilt belum dipin versinya (sama seperti sebelumnya); nama label pod dan target sidecar (`nats-0.nats-headless:7777`) mengikuti chart 2.x.
